Neighbourhood Protocol

A choice-based narrative about community, surveillance, and mutual aid

Role Developer & Interaction Designer
Illustration Anna
Year 2025
Tech HTML / CSS / JS / GSAP

Overview

Three scenes. Three choices. Each one grounded in documented tactics used by real mutual aid networks.

Neighbourhood Protocol is a choice-based narrative experience about the everyday decisions that define community. The experience puts you inside three scenarios — each one quiet, each one weighted — and asks what you would do. It ends with a reminder that none of it is fiction.

Collaboration

The illustrations came first. The interface had to catch up.

Anna's flat editorial style set the terms for everything else. Each scene arrived as a sequence of still frames — flat fills, a deliberate palette, a visual language that felt closer to print than screen. My job was to figure out how to make a browser feel like it deserved these images.

Anna's illustrations weren't designed for screens — that restraint was a design principle, not a limitation. Every UI decision I made — typography weight, spacing, button style — had to stay invisible enough that the illustrations could dominate without competition.

The harder problem was that the web is rhizomatic: it branches, loops, forks back on itself. Anna's frames were sequential. Bridging the two meant rethinking how each illustration needed to function — not just as a static image, but as a state in a branching system. Some frames needed to appear, hold, then dissolve based on a choice the user had made several steps earlier.

Design Technique

To keep Anna's flat illustrations from looking like dropped-in PNGs, I leaned heavily on CSS blend modes. Setting images to mix-blend-mode: multiply against tinted backgrounds let the illustrations absorb the page's colour temperature — making them feel embedded rather than placed. The result is that the scenes look like they belong to the browser, not pasted into it.

Building the Engine

Vanilla JavaScript, no frameworks. A scene engine handles branching narrative state, image sequencing, and routing between choices. GSAP drives the transitions — deliberate, unhurried pacing that matches the weight of each decision. Narrative data lives in separate JS modules, keeping story logic clean and extensible.

The phone and camera UI components came directly from Anna's designs — she drew the frames, I built the CSS to surround them. Interface and illustration share the same visual DNA rather than one feeling bolted onto the other.
